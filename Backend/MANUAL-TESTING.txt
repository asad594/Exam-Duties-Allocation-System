=======================================================================
            EDAS - EXAM DUTIES ALLOCATION SYSTEM
            MANUAL API TESTING GUIDE  (using Postman Desktop)
=======================================================================

HOW TO USE THIS GUIDE
- Do the sections IN ORDER, from Section 1 to Section 10.
- Every test shows:  REQUEST, BODY (if any), EXPECTED STATUS,
  EXPECTED OUTPUT. Compare what Postman shows with EXPECTED OUTPUT.
- Put an X in the box [ ] when your result matches.
- Values in < > change every time (tokens, times). Only check that
  they are present.
- All IDs in this guide are correct when you start from a FRESH
  database (Section 1, Step 1.4). If an ID is different on your
  screen, use the ID you see.


=======================================================================
SECTION 1 - PREPARATION (do once before testing)
=======================================================================

Step 1.1  Start Docker
   Open Docker Desktop from the Start menu.
   Wait until the bottom-left corner shows "Engine running".
   NOTE: Only the container "edas-mysql" belongs to this project.
         Do not stop or change any other container.

Step 1.2  Open a terminal in the Backend folder
   Folder: C:\Users\RB Tech\Desktop\Software Construntion project\Backend
   (Right-click inside the folder -> "Open in Terminal", or Git Bash.)

Step 1.3  Start the EDAS database
   Type:      docker start edas-mysql
   EXPECTED:  edas-mysql

Step 1.4  Make the database fresh (recommended, gives the IDs below)
   Type:      dotnet tool run dotnet-ef database drop -f --project Edas.Api
   EXPECTED:  Successfully dropped database 'edas'.
              (If it says the database does not exist, that is fine.)

Step 1.5  Start the API
   Type:      dotnet run --project Edas.Api --launch-profile http
   EXPECTED:  ... Now listening on: http://localhost:5080
   Keep this terminal open while testing. On first start the API
   creates all tables and loads the sample data by itself.

Step 1.6  Import the collection into Postman
   Postman -> Import (top left) -> files ->
   Backend\postman\EDAS.postman_collection.json -> Import.
   EXPECTED:  Collection "EDAS - Exam Duties Allocation System" with
              folders Auth, Staff, Rooms, Courses, Sessions, Slots,
              Unavailabilities, Rosters, My Duties.
   (If an older copy is already imported, delete it first.)

Step 1.7  How to work in Postman
   - Click a request in the left sidebar, then click the blue "Send".
   - Status code is shown at the top right of the response
     (e.g. "200 OK").
   - To change the JSON you send: "Body" tab.
   - To change an ID: edit the number at the end of the URL bar.
   - To change filters: "Params" tab.
   - Collection variables (baseUrl, accessToken, refreshToken,
     rosterId): click the collection name -> "Variables" tab.

[ ] Test 2.1  Coordinator login
    REQUEST:   Auth -> Login (coordinator)    POST /api/auth/login
    BODY:      { "email": "coord@edas.test", "password": "Coord@123" }
    EXPECTED STATUS:  200 OK
    EXPECTED OUTPUT:
       {
         "accessToken": "<long text starting with eyJ>",
         "refreshToken": "<long random text>"
       }
    NOTE: Postman saves both tokens automatically. Every other
          request now sends the access token.

[ ] Test 2.2  Wrong password is rejected
    REQUEST:   Auth -> Login (coordinator), change password to "wrong"
    EXPECTED STATUS:  401 Unauthorized
    EXPECTED OUTPUT:
       { "title": "Invalid email or password.", "status": 401 }
    AFTER: change the password back to Coord@123 and Send again (200).

[ ] Test 2.3  Refresh gives a new pair of tokens
    BEFORE: from the last login response copy the "refreshToken"
            value (without quotes) into Notepad.
    REQUEST:   Auth -> Refresh    POST /api/auth/refresh
    BODY:      { "refreshToken": "{{refreshToken}}" }
    EXPECTED STATUS:  200 OK
    EXPECTED OUTPUT:  new "accessToken" and new "refreshToken"
                      (different from before).

[ ] Test 2.4  A refresh token works only once
    REQUEST:   Auth -> Refresh. In Body replace {{refreshToken}} with
               the OLD token you copied in Test 2.3.
    EXPECTED STATUS:  401 Unauthorized
    EXPECTED OUTPUT:
       { "title": "Invalid refresh token.", "status": 401 }
    AFTER: put {{refreshToken}} back in the Body.

[ ] Test 2.5  No token = not allowed
    REQUEST:   Rooms -> List Rooms. "Authorization" tab -> "No Auth".
    EXPECTED STATUS:  401 Unauthorized
    EXPECTED OUTPUT:  (empty body)
    AFTER: set Authorization back to "Inherit auth from parent".

[ ] Test 2.6  Staff cannot use coordinator endpoints
    REQUEST:   Auth -> Login (staff)   (ali@edas.test / Staff@123)
    EXPECTED STATUS:  200 OK (tokens saved)
    THEN:      Rooms -> List Rooms -> Send
    EXPECTED STATUS:  403 Forbidden
    EXPECTED OUTPUT:  (empty body)

[ ] Test 2.7  Log in as coordinator again (needed for Sections 3-8)
    REQUEST:   Auth -> Login (coordinator)
    EXPECTED STATUS:  200 OK

    REMEMBER: the access token is valid for 15 minutes. If you get an
    unexpected 401 later, run Auth -> Refresh or log in again.

=======================================================================
STATUS CODE MEANINGS
=======================================================================
200 OK            the request worked
201 Created       a new record was created
204 No Content    deleted / logged out (empty body)
400 Bad Request   invalid input (missing field, bad email, end < start)
401 Unauthorized  not logged in, wrong password, expired or used token
403 Forbidden     logged in but not allowed (staff on coordinator API)
404 Not Found     the id does not exist
409 Conflict      duplicate value, or the record is still in use
422 (rule)        a business rule rejected the change; read "reason"
